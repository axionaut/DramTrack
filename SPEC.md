DramTrack Pro — Living Specification
====================================

Location: `SPEC.md` (root)

Overview
--------
DramTrack Pro is a Streamlit app to maintain personal whiskey rankings and perform pairwise "duels" to place a new bottle into a user's ranked list.

Primary Features
----------------
- Authenticate (optional) via Google (sidebar).
- Load master whiskey library from Google Sheets (`Your Next Whiskey`, worksheet `Whiskeys`).
- Allow users (guest or logged-in) to build a personal ranked list (Leaderboard).
- Add a new bottle via `Add & Rank a Bottle` select box and insert it using a binary-search style duel.
- Duel UI: shows two bottle images side-by-side with centered selection buttons.
- Disk-backed image cache: downloaded images are cached on-disk to reduce repeated network requests.

Architecture & Data Flow
------------------------
- Streamlit frontend (single-process web app).
- Data: Google Sheets → `gspread` client → DataFrame cached in `st.session_state.master_library`.
- User data: stored per-user CSV under `user_data/` or `guest_rankings.csv`.
- Images:
  - Image URLs are generated by `get_whiskey_image(name)` (Bing image URL with query).
  - `fetch_cached_image_bytes(name)` downloads and caches bytes in `image_cache/` and returns bytes for `st.image`.
  - No persistent image processing is applied (background-removal and shadow experiments were reverted).

- Added Recommendation Engine (2026-01-16):
  - Feature: Recommends five whiskeys based on the user's current top-ranked bottle.
  - Algorithm: Finds whiskeys not already in user's list with ratings just above the user's top whiskey; if less than five higher-rated bottles are available, includes closest lower-rated bottles by absolute rating difference.
  - UI: Displays five recommendations (images + name + rating) under the Leaderboard with an `Add` button to append the bottle to the user's list.
  - Notes: Recommendations exclude items already present in the user's list.
  - Tie-breaking: When choosing among higher-rated candidates, use the numeric `Value` as a tie-breaker (higher `Value` preferred). Do NOT use `Value` to promote lower-rated bottles — `Value` only applies when the candidate's rating is above the user's top rating.
    - Implementation detail: the master library is now normalized and sorted on import by `Weighted_Rating` (desc), then `Value_Num` (desc), then `Price_Num` (asc), then `Name` (asc). `Weighted_Rating` is a Bayesian-style weighted average using the whiskey's `Count` and a small prior.
      - Formula used: `Weighted_Rating = (Rating * Count + prior_count * prior_mean) / (Count + prior_count)` where `prior_count=5` and `prior_mean` is the global mean of ratings in the library.
      - `Weighted_Rating` is used for ranking, recommendation selection, and internal scoring where available.

Current Runtime Behavior (summary)
---------------------------------
- On startup, the app caches the master library from Google Sheets (1 hour TTL).
- The user selects a bottle to add; if eligible, the app enters a duel sequence using binary insertion into the user's list.
- Images shown in duels are loaded from the cached PNG/JPEG bytes. If not cached, the app downloads and caches them.

Performance & Scalability Notes
-------------------------------
- Current caching is local-disk based (`image_cache/`). This is efficient for a single instance but must be replaced with a shared blobstore (S3/Blob) or CDN for multi-instance deployments.
- Image downloads are synchronized with a simple lock-file to avoid duplicate downloads under concurrency.
- Heavy image processing (OpenCV / ML) was intentionally reverted because it increased CPU load and produced inconsistent results.

Security & Operational Notes
----------------------------
- Ensure `data/service_account.json` is kept secret and the Google Sheet is shared with the service account email.
- For production, run Streamlit behind a proper WSGI gateway or reverse proxy and scale app instances horizontally with shared storage for cached images.
